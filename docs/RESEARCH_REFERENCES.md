# Research references and implementation boundaries

The [current literature review and study protocol](RESEARCH_PROTOCOL.md) covers the 2026 CSCW hidden-profile experiments, grounding theory, the original human decision-making experiments, and the author-hosted AMJ paper. The [dialogue methods](HUMAN_DIALOGUE.md) document the human corpus and held-out validation. The [DeepSeek price table](https://api-docs.deepseek.com/quick_start/pricing/) informed model aliases and conservative peak-rate budgeting.

Inspected on 17 November 2026. These sources informed a small independent implementation; no research framework, town engine, or benchmark package was copied into this project. Repository paths below identify the architecture actually inspected, rather than implying that its experimental results apply here.

| Original source | Inspected material | Pattern used in this MVP |
|---|---|---|
| [Generative Agents paper](https://arxiv.org/abs/2304.03442) and [repository](https://github.com/joonspk-research/generative_agents) | `reverie/backend_server/persona/persona.py`; `memory_structures/associative_memory.py`; `cognitive_modules/plan.py`; `environment/frontend_server/translator/views.py`. The persona pipeline separates perception, retrieval, planning, reflection and execution; frontend replay consumes recorded movement. | Separate agent context and episodic records from the scheduler. Persist a project across days. Render movement from recorded events. We use finite work blocks and bounded memory, not their open-ended planning, reflection scoring or simulation frontend. |
| [World of SWECraft paper](https://arxiv.org/abs/2610.24061) and [launcher](https://github.com/software-worlds/swecraft-launcher) | READMEs under `services/coordinator`, `services/runner`, `services/evaluator`; `coordinator/src/swecraft_coordinator/scheduler.py` and `state.py`; `runner/src/swecraft_runner/runner.py`. | Persistent next-due scheduling, transactional execution claims, isolated turn accounting and checkpointing before evaluation. The local MVP does not run agents in Docker or modify a real software repository. |
| [MultiAgentBench paper](https://aclanthology.org/2025.acl-long.421/) and [MARBLE](https://github.com/ulab-uiuc/MARBLE) | README; `marble/engine/engine.py`; `marble/environments/base_env.py`; `marble/evaluator/evaluator.py`. | Keep environments, action validation, agent execution, memory and evaluation modular. Count milestones and resource use. The MVP deliberately avoids adopting subjective LLM-judged communication scores as objective cooperation measurements. |
| [CollabSim](https://arxiv.org/abs/2606.06399), [full text](https://arxiv.org/html/2606.06399v2) | Sections 3.1–3.3, Appendix A and limitations: validated controller actions, public/private context, communication restrictions and structured traces. | Enforce conditions in the engine, control what each turn can see, and preserve action evidence for later isolation probes. Agent statements about cooperation are not treated as verified behavior. |
| [Workplace small-talk study](https://doi.org/10.5465/amj.2018.1474) | Publisher/DOI full text was blocked by access restrictions. Bibliographic identity was checked against [an author's university-hosted CV](https://smlr.rutgers.edu/sites/default/files/Documents/Faculty-CV/Methot_Jessica_CV_July24.pdf). | Motivates measuring possible benefits and distraction costs separately. No detailed effect size or causal claim from this inaccessible full text is used. Human workplace findings do not establish artificial feelings. |
| [Small talk and employee safety performance](https://pmc.ncbi.nlm.nih.gov/articles/PMC12380899/) | The PMC page required a browser challenge. The article's metadata and abstract were retrieved through the [Europe PMC record API](https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=PMCID%3APMC12380899&format=json) and [full-text XML](https://www.ebi.ac.uk/europepmc/webservices/rest/PMC12380899/fullTextXML). The abstract describes questionnaires from 136 employees and opposing resource-gain/resource-loss pathways. | Treat human evidence as motivation and acknowledge both possible directions of an effect. This is not an intervention trial on LLM teams and does not validate the simulator. |
| [Google Research Sleep framework](https://research.google/blog/the-sleep-framework-a-new-way-for-llms-to-retain-knowledge-in-continual-learning/) | The original 27 October 2026 article, including its active/sleep phases and parameter consolidation/dreaming sections. | A clear **non-implementation boundary**: that research updates numerical model parameters. Our sleep phase only persists local event/snapshot memory. It does not train, fine-tune, expand experts, dream, or alter a provider model. |

## Provider documentation inspected

- Gemini [model description](https://aistudio.google.com/docs/models/gemini-3.5-flash-lite), [stateless REST text generation](https://aistudio.google.com/docs/text-generation?generate-content=true), [structured JSON output](https://aistudio.google.com/docs/structured-output?generate-content=true), [token counts](https://aistudio.google.com/docs/tokens?generate-content=true), [pricing](https://aistudio.google.com/docs/pricing), [API-key handling](https://aistudio.google.com/docs/api-key), [model listing](https://aistudio.google.com/api-reference/models/list-models), [quota scope](https://ai.google.dev/gemini-api/docs/rate-limits) and [retry guidance](https://aistudio.google.com/docs/troubleshooting). The adapter uses native `generateContent`, one attempt at a time, rather than a provider-managed conversation. The engine owns retries and memory. Model access, quota and billing are deployment-specific; documentation is not proof that supplied credentials work.
- [Google RetryInfo](https://docs.cloud.google.com/java/docs/reference/proto-google-common-protos/latest/com.google.rpc.RetryInfo) describes waiting for server retry guidance and progressively backing off. Unknown-project credentials share one conservative cooldown; new keys do not multiply project quota.
- [OpenAI Chat Completions API](https://developers.openai.com/api/reference/resources/chat) informed the optional compatible adapter. Compatibility is only established by the local mocked HTTP tests until a specific endpoint/model is tested with an authorized key.

All dates and model prices are reference checkpoints, not promises of future availability. Live acceptance results belong in `FINAL_HANDOFF.md`; mock results are synthetic software-verification data.
